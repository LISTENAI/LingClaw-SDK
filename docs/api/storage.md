# storage · 应用存档

最低 API 版本：3。存档按应用 ID 隔离，容量与有效期由运行环境配置决定。

## storage.load()

最低 API 版本：3。

**作用：** 读取当前应用的存档。

无参数。返回当前应用 ID 的存档表，或 `nil`（没有存档、过期、未校时或不可用）。
读取不会延长有效期。应用应检查旧数据的字段类型与范围。

## storage.save(data[, ttl_seconds])

最低 API 版本：3。

**作用：** 保存当前应用的数据，完整替换原存档。

- `data`：table，完整替换该应用原存档。
- `ttl_seconds`：可选正整数，有效期，单位秒；默认 604,800，最多 2,592,000。
- 返回：成功 `true`；失败 `false, reason`，`reason` 为字符串。

最多 32 项；键是 1–32 字节字符串，值是有限数字、布尔值或最多 256 字节字符串。
不支持嵌套和 NUL 字符。序列化总大小默认最多 1,024 字节。
默认最多保存 4 个应用的存档，同一槽写入至少间隔 10 秒。
具体额度取 capabilities 的 `runtime.lua_sdk.storage`。

启动期间写入暂存到候选实例，启动成功后再尝试持久化；此时 `true` 只表示接受暂存。
启动失败不会提交暂存内容。运行期间成功返回表示已经完成写入。

常见失败原因：`clock_unavailable`、`rate_limited`、`too_large`、`invalid_data`、
`invalid_ttl`、`storage_full`、`io_error`、`no_memory`、`unavailable`。

## storage.clear()

最低 API 版本：3。

**作用：** 清除当前应用的存档。

无参数。显式清除当前应用的存档，未校时也可调用。
返回成功 `true`，失败 `false, reason`，`reason` 为字符串。
清除及退出不会重置写入间隔。

读取过存档的应用若发生 Lua 异常，运行器尝试清除该应用的存档，
使下次可以从空数据启动。底层存储故障仍可能导致清除失败。

模拟器使用本机应用数据目录保存独立存档，按所打开文件的文件名主干区分应用。
未指定文件时使用 `untitled`。这份存档不与设备同步。
